## ما الذي يتضمنه المشروع

**واجهة المتجر**
- صفحة رئيسية: شريط إعلانات قابل للتعديل، بحث مع اقتراحات تلقائية، اختيار الجهاز (الشركة ← الموديل ← نوع القطعة)، الأقسام، منتجات مميزة، عروض حقيقية فقط (سعر سابق أعلى)، الأكثر مبيعاً (من الطلبات المُسلّمة فعلياً)، وصل حديثاً، قسم الفنيين، قسم واتساب، عناصر ثقة تظهر فقط إذا أدخلها المالك.
- 12 قسماً رئيسياً وأكثر من 110 قسم فرعي حسب المواصفات — كلها قابلة للتعديل.
- نظام توافق الأجهزة: الشركة ← السلسلة ← الموديل ← النسخة ← المنتج، مع حالة توافق (مؤكد / غير مؤكد / غير معروف) وتحذيرات واضحة.
- بيانات أولية لـ 16 شركة مصنعة وأكثر من 170 موديل حقيقي (أرقام الموديل الرسمية تُضاف من المالك بعد التحقق).
- بحث عربي/إنجليزي يتعامل مع اختلافات الإملاء (أ/إ/آ/ا، ة/ه، ى/ي، التشكيل، الأرقام العربية) ومع مرادفات مثل «ايفون = iPhone» و«شاشة = screen»، ويبحث في: الاسم، SKU، الباركود، أرقام القطعة، الموديلات وأرقامها، القسم، نوع القطعة، والكلمات الإضافية. مفهرس بفهرس trigram في PostgreSQL.
- فلاتر: القسم، الشركة، الموديل، نوع القطعة، الحالة، السعر، التوفر، حالة التوافق + ترتيب وتقسيم صفحات.
- صفحة المنتج: معرض صور مع تكبير، المواصفات، التوافق، الحالة، الجودة، الضمان، سعر الجملة، المخزون، منتجات مرتبطة وبديلة، أضف للسلة، اشترِ الآن، استفسار واتساب.
- السلة: محفوظة في المتصفح، والأسعار والمخزون والخصومات والمجاميع **تُحسب دائماً على الخادم**.
- إتمام الطلب كضيف أو بحساب، الدفع عند الاستلام، رقم طلب فريد، منع الطلبات المكررة، خصم المخزون داخل معاملة قاعدة بيانات تمنع البيع الزائد.
- صفحة تأكيد الطلب برابط سري غير قابل للتخمين + مشاركة الطلب عبر واتساب + صفحة تتبع (رقم الطلب + رقم الهاتف).
- حسابات زبائن اختيارية: تسجيل/دخول، طلباتي، إعادة الطلب، العناوين، تغيير كلمة المرور، إعادة تعيين آمنة.
- خريطة الموقع، robots.txt، بيانات Open Graph، روابط canonical، بيانات منتج منظمة (Schema.org) للمنتجات الحقيقية فقط.

**لوحة التحكم** (`/admin`)
- نظرة عامة بإحصاءات حقيقية: الطلبات حسب الحالة، المبيعات للفترة، الأكثر مبيعاً، المخزون المنخفض، حركات المخزون، آخر العمليات.
- المنتجات: إضافة/تعديل/أرشفة، صور متعددة (تُضغط وتُخزن في قاعدة البيانات)، التسعير والجملة والتكلفة، التوافق، المنتجات المرتبطة والبديلة، استيراد/تصدير CSV.
- المخزون: إدخال، إخراج، تسوية جرد بسبب إلزامي، سجل حركات كامل باسم المستخدم والوقت، منع المخزون السالب (في الكود وفي قاعدة البيانات)، قيمة المخزون، تنبيهات النقص.
- الطلبات: بحث بالرقم/الهاتف/الاسم، فلاتر بالتاريخ والحالة، تغيير الحالة بمسار منطقي، سبب إلغاء إلزامي، إعادة المخزون عند الإلغاء، تسجيل المدفوعات، الشحن، ملاحظات داخلية، تعديل أجرة التوصيل، سجل الحالات، طباعة الفاتورة (A4 / 80مم / 58مم)، تصدير CSV. **لا يمكن حذف الطلبات** — تبقى للتدقيق.
- الأقسام، الشركات/السلاسل/الموديلات/النسخ، أنواع القطع، حالات المنتج.
- الزبائن (مع توليد رابط إعادة تعيين كلمة المرور)، الموردون، أوامر الشراء مع الاستلام للمخزون وتحديث التكلفة.
- التقارير: يومي/أسبوعي/شهري/فترة مخصصة، حسب المنتج والقسم والشركة والموديل، الخصومات، التوصيل، صافي المبيعات، النقد المقبوض، تكلفة البضاعة، الربح التقديري، قيمة المخزون، الحركات، الملغاة، مشتريات الموردين — مع طباعة وتصدير CSV.
- أكواد الخصم، طرق وأجور التوصيل حسب المحافظة، إعدادات المتجر، المستخدمون الإداريون والصلاحيات، سجل العمليات.

## التقنيات المستخدمة

| المجال | الاختيار |
|---|---|
| الإطار | Next.js 16 (App Router) + React 19 + TypeScript |
| التصميم | Tailwind CSS 3 مع نظام تصميم خاص، خط IBM Plex Sans Arabic (مستضاف داخل المشروع)، أيقونات lucide |
| قاعدة البيانات | PostgreSQL 16 + Prisma ORM 6 مع ترحيلات (migrations) |
| الصور | تُخزن داخل PostgreSQL بصيغة WebP مضغوطة (sharp) — لا حاجة لخدمة تخزين منفصلة |
| المصادقة | جلسات على الخادم مخزنة في قاعدة البيانات، كلمات مرور bcrypt، كوكي httpOnly |
| الاختبارات | Vitest (وحدات) + Playwright (من البداية للنهاية) |
| النشر | Docker / docker-compose، أو أي منصة Node.js مع PostgreSQL |

## التشغيل محلياً

المتطلبات: Node.js 22، PostgreSQL 14+.

```bash
npm install
```

```bash
cp .env.example .env
```

عدّل `DATABASE_URL` في `.env`، ثم:

```bash
npx prisma migrate deploy
```

```bash
npm run db:seed
```

(أو `npm run db:seed:demo` لإضافة 17 منتجاً تجريبياً موسوماً بوضوح لعرض الموقع.)

```bash
npm run admin:create
```

```bash
npm run dev
```

افتح `http://localhost:3000` والمتجر، و`http://localhost:3000/admin` للوحة التحكم.

## إنشاء حساب المالك بأمان

لا توجد أي كلمة مرور مكتوبة في الكود. طريقتان:

**1) من سطر الأوامر (موصى به):**

```bash
npm run admin:create
```

يسألك عن البريد والاسم وكلمة المرور (10 أحرف على الأقل، أحرف وأرقام). أول حساب يكون «المالك». يمكن أيضاً تمريرها عبر `ADMIN_EMAIL` و`ADMIN_PASSWORD` و`ADMIN_NAME` كمتغيرات بيئة مؤقتة. لإعادة تعيين كلمة مرور مدير:

```bash
npm run admin:create -- --reset
```

**2) من المتصفح (للاستضافات التي لا توفر سطر أوامر):** ضع قيمة عشوائية طويلة (24 حرفاً فأكثر) في متغير البيئة `SETUP_TOKEN`، ثم افتح `/admin/setup`. الصفحة تعمل **فقط** إذا لم يوجد أي مالك/مدير، وتختفي بعد الإنشاء. احذف `SETUP_TOKEN` بعدها.

الأدوار: **المالك** (كل شيء)، **المدير** (كل شيء عدا إدارة المستخدمين)، **الموظف** (الطلبات، المخزون، المنتجات بدون تعديل الأسعار/التكلفة، الزبائن — بدون التقارير المالية والإعدادات).

## النشر على الإنترنت

> **لم يتم النشر بعد**: لا تتوفر في بيئة التطوير بيانات دخول لأي خدمة استضافة أو قاعدة بيانات. الخطوات أدناه جاهزة للتنفيذ عند توفرها.

المهم: البيانات (الطلبات، المخزون، الصور) محفوظة في PostgreSQL، لذلك يجب أن تكون قاعدة البيانات **دائمة** (لا تستخدم قاعدة بيانات مؤقتة تُمسح عند إعادة التشغيل).

### الخيار أ (موصى به للمتجر التجاري): خادم VPS + Docker
تكلفة شهرية منخفضة وثابتة (خوادم VPS صغيرة متوفرة عادة بحوالي 4–6 دولار شهرياً — تحقق من السعر الحالي لدى المزود)، بلا قيود «الاستخدام غير التجاري»، وقاعدة البيانات على قرص دائم.

```bash
git clone https://github.com/ibrahim205b-tech/hamode.git
```

```bash
cd hamode && cp .env.example .env
```

اضبط في `.env`: `POSTGRES_PASSWORD` (كلمة قوية)، `NEXT_PUBLIC_SITE_URL` (رابط موقعك). ثم:

```bash
docker compose up -d --build
```

```bash
docker compose exec app npm run db:seed
```

```bash
docker compose exec app npm run admin:create
```

ضع أمام التطبيق خادماً عكسياً مع شهادة HTTPS (مثل Caddy أو Nginx + Let's Encrypt). خذ نسخاً احتياطية دورية من قاعدة البيانات:

```bash
docker compose exec db pg_dump -U hammoudi hammoudi > backup-$(date +%F).sql
```

### الخيار ب: منصة مُدارة (Vercel + Neon)
- **Vercel**: خطة Hobby المجانية **مخصصة للاستخدام الشخصي غير التجاري فقط** حسب شروط Vercel، والمتجر نشاط تجاري ⇐ يلزم خطة Pro (حوالي 20 دولار شهرياً حسب المصادر الحالية).
- **Neon (PostgreSQL)**: الخطة المجانية حالياً 0.5 جيجابايت تخزين و100 ساعة حوسبة شهرياً لكل مشروع، ويتوقف الحساب عند تجاوزها. 0.5 جيجابايت تكفي لبداية صغيرة (الصور المضغوطة ~100–200 كيلوبايت لكل صورة)، لكن مع نمو الكتالوج ستحتاج خطة مدفوعة. راجع شروط الاستخدام التجاري في موقع Neon.
- اضبط في المنصة: `DATABASE_URL`، `NEXT_PUBLIC_SITE_URL`، ثم نفّذ `npx prisma migrate deploy` و`npm run db:seed` مرة واحدة على قاعدة البيانات، وأنشئ المالك عبر `/admin/setup` مع `SETUP_TOKEN`.

> الأسعار والحدود تتغير — تحقق منها في مواقع المزودين قبل الاشتراك.

## إضافة المنتجات الحقيقية واستيراد المخزون

1. **احذف المنتجات التجريبية**: لوحة التحكم ← الإعدادات ← «حذف كل المنتجات التجريبية» (أو أخفها بإلغاء «إظهار المنتجات التجريبية»).
2. **منتج واحد**: المنتجات ← منتج جديد ← احفظ ← ارفع الصور ← اربط الموديلات المتوافقة (استخدم «توافق مؤكد» فقط بعد التحقق الفعلي).
3. **بالجملة عبر Excel/CSV**:
   - المنتجات ← استيراد/تصدير ← نزّل «قالب فارغ» و«مرجع الأقسام والموديلات».
   - املأ الملف في Excel واحفظه بصيغة **CSV UTF-8**.
   - ارفعه مع خيار «فحص فقط» أولاً؛ إذا ظهر أي خطأ لن يتغير شيء. ثم ارفعه بدون الفحص.
   - المنتجات تُطابق حسب SKU: الموجود يُحدَّث والجديد يُنشأ. عمود `stockQty` يحدد الرصيد ويُسجل الفرق كحركة مخزون.
   - عمود `compatibleModels` مثل: `iphone-13-pro:VERIFIED|iphone-13:UNKNOWN`.
4. **البضاعة من الموردين**: الموردون ← أمر شراء جديد ← «استلام البضاعة» لإضافتها للمخزون مع تكلفتها (تُستخدم في تقارير الربح وقيمة المخزون).

## الإعدادات التي تحتاج إدخالك

هذه المعلومات **لم تُخترع** وتبقى مخفية حتى تدخلها من لوحة التحكم ← الإعدادات / التوصيل:
- العنوان، أوقات العمل، هاتف الاتصال، البريد، رابط الخريطة، روابط التواصل الاجتماعي.
- سياسات التوصيل والإرجاع والضمان والخصوصية والشروط.
- عناصر الثقة في الصفحة الرئيسية.
- **أجور التوصيل**: طريقتا التوصيل معطلتان افتراضياً. قبل تفعيلها تُقبل الطلبات وتظهر للزبون عبارة «تُحدد أجرة التوصيل عند التأكيد»، ويمكنك إدخال الأجرة من صفحة الطلب.
- الأسعار الحقيقية والمخزون وأرقام الموديل الرسمية.

**الخدمات التي تتطلب بيانات دخولك:** استضافة (VPS أو Vercel)، قاعدة بيانات PostgreSQL دائمة، نطاق (Domain). لا توجد أي خدمة مدفوعة إلزامية أخرى.

**غير مُنفّذ عمداً (لعدم توفر خدمة حقيقية):**
- الدفع الإلكتروني بالبطاقات — الموقع لا يدّعي توفره. البنية تسمح بإضافة مزود دفع لاحقاً كطريقة دفع جديدة.
- WhatsApp Business API — الموقع يستخدم روابط click-to-chat الرسمية. الرسائل تُبنى في `src/lib/whatsapp.ts` ويمكن إرسالها عبر API لاحقاً من نفس المكان.
- إرسال البريد الإلكتروني/SMS — إعادة تعيين كلمة مرور الزبون تتم برابط آمن لمرة واحدة يولّده الموظف ويرسله عبر واتساب.

## قواعد المحاسبة في التقارير

- **المبيعات المكتملة** = الطلبات بحالة «تم التسليم» فقط، حسب تاريخ التسليم.
- **الطلبات الملغاة** لا تدخل في أي إيراد أو ربح، ويُعاد مخزونها، وتظهر في تقرير مستقل.
- **إجمالي المبيعات** = أسعار المنتجات قبل الخصم. **صافي المبيعات** = الإجمالي − الخصومات (بدون التوصيل).
- **المستحق من الزبائن** = صافي المبيعات + أجور التوصيل. **النقد المقبوض** = الدفعات المسجلة فعلياً حسب تاريخ القبض.
- **تكلفة البضاعة المباعة** = تكلفة الوحدة المحفوظة لحظة الطلب × الكمية. **الربح الإجمالي التقديري** يُحسب فقط للبنود التي لها تكلفة، مع عرض نسبة تغطية بيانات التكلفة؛ ولا يُعرض ربح بدون بيانات تكلفة.
- **قيمة المخزون** = الرصيد × آخر تكلفة مسجلة (المنتجات التجريبية والمؤرشفة مستبعدة).
- **المشتريات** تكاليف وليست إيرادات.

## الأمان

- تحقق الصلاحيات على الخادم في كل صفحة وكل إجراء إداري (وليس إخفاء روابط فقط)، مع طبقة حماية أولى في `src/proxy.ts`.
- كلمات مرور bcrypt (12 جولة)، جلسات عشوائية تُخزن مُجزّأة (SHA-256) في قاعدة البيانات، كوكي httpOnly + SameSite + Secure في الإنتاج، إنهاء الجلسات عند تغيير كلمة المرور.
- حماية من تخمين كلمات المرور وتحديد معدل الطلبات (مخزن في قاعدة البيانات) لتسجيل الدخول، إنشاء الطلبات، التتبع، البحث.
- حماية CSRF: إجراءات الخادم في Next.js تتحقق من المصدر تلقائياً، ونقاط API الحساسة تتحقق من ترويسة Origin.
- Prisma (استعلامات مُعاملة) ضد حقن SQL، وReact يهرّب المخرجات ضد XSS، وحماية من حقن الصيغ في ملفات CSV.
- رفع الصور: التحقق من النوع والحجم وفحص المحتوى الفعلي عبر sharp وإعادة الترميز إلى WebP.
- روابط الطلبات سرية (256 بت)، والتتبع يتطلب رقم الطلب + الهاتف، والحسابات لا تُربط بطلبات ضيوف سابقة (لأن رقم الهاتف غير مُتحقق منه).
- التكلفة وبيانات الموردين لا تُرسل للمتصفح العام أبداً؛ الموظف لا يستطيع تعديل الأسعار.
- سجل عمليات لكل الإجراءات الحساسة (الأسعار، المخزون، الحالات، الإعدادات، الدخول، التصدير).
- لا أسرار في الكود: كلها في متغيرات البيئة (`.env` مستبعد من Git).

**ملاحظة تدقيق الحزم:** `npm audit` يُظهر تحذيراً في حزمة `deepmerge-ts` المستخدمة داخل أداة Prisma CLI (تُستخدم وقت البناء والترحيل فقط ولا تتعامل مع مدخلات المستخدمين). الإصلاح يتطلب الترقية إلى Prisma 7 (تغيير جذري) — يُنصح بها في تحديث لاحق.

## الطباعة والطابعات الحرارية

- الفواتير: لوحة التحكم ← الطلب ← «فاتورة A4» أو «إيصال 80مم» أو «إيصال 58مم».
- التقارير: صفحة التقارير ← «طباعة» (تحترم الفترة والقسم المختار).
- تعمل الطباعة عبر نافذة الطباعة في المتصفح، ويمكن «الحفظ كـ PDF».
- للطابعات الحرارية: ثبّت تعريف الطابعة في نظام التشغيل، اختر حجم الورق المطابق (58 أو 80 مم)، وألغِ الهوامش والرأس/التذييل في نافذة الطباعة. **الطباعة المباشرة عبر البلوتوث من المتصفح غير مضمونة** في كل المتصفحات ولم تُنفّذ؛ الطريقة المعتمدة هي طباعة المتصفح عبر تعريف الطابعة.

## واتساب

- الرقم المركزي: الإعدادات ← «رقم واتساب الرسمي» (افتراضياً `07700733822` ⇐ `9647700733822`). يُتحقق منه ويُحوّل للصيغة الدولية تلقائياً.
- يُستخدم في: الزر العائم في كل الصفحات (يُخفى على الجوال في السلة والدفع حتى لا يغطي الأزرار)، استفسار المنتج (الاسم، SKU، الموديل، الرابط)، مشاركة السلة (مع توضيح أن المجموع تقديري)، مشاركة الطلب بعد إنشائه، الفوتر، صفحة التواصل.
- الموقع يوضح أن الطلب مسجّل في المتجر أصلاً، وأن فتح واتساب خطوة منفصلة لا ترسل شيئاً حتى يضغط الزبون «إرسال».
